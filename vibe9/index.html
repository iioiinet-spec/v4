01 — Blueprint

같은 AI, 다른 결과

두 학생이 같은 도구로 같은 앱을 만들려 합니다. 결과가 갈리는 지점은 실력이 아니라 부탁한 문장의 구체성입니다. 카드를 눌러 무엇이 달랐는지 확인해 보세요.

02 — Anatomy

프롬프트를 이루는 다섯 덩어리

순서대로 채우면 빠지는 것이 없습니다. 아래 빌더도 정확히 이 순서로 문장을 조립합니다.

환경 / STACK

무엇으로 만들까

언어, 라이브러리, 파일 구조. “파이썬으로”만으로는 부족합니다. PySide6로, 단일 파일로까지 적습니다.

동작 / BEHAVIOR

무엇을 할까

사용자가 눈으로 확인할 수 있는 문장만 씁니다. “예쁘게”는 확인이 안 되고, “클릭하면 말풍선이 3초간 뜬다”는 확인이 됩니다.

제약 / RULES

하지 말아야 할 것

제목 표시줄 없애기, 배경 투명 처리, 화면 밖으로 못 나가게 하기. 안 적으면 기본값이 들어옵니다.

데이터 / STATE

무엇을 기억할까

위치·크기·대사. 껐다 켜도 유지되어야 하는 것을 지정합니다. pet_config.json에 저장처럼 파일 이름까지.

검증 / CHECK

어떻게 확인할까

학생들이 가장 많이 빠뜨리는 칸입니다. “안 보이면 로그를 남길 것”을 미리 적으면, 실패했을 때 원인을 스스로 찾습니다.

한 줄 규칙

눈으로 확인 가능한가?

문장을 하나 쓸 때마다 물어보세요. “이게 됐는지 화면을 보고 판단할 수 있나?” 아니라면 그 문장은 아직 명세가 아닙니다.

03 — Builder · 이 페이지의 핵심

문장을 켜면, 캐릭터가 바뀐다

체크 목록은 설계도, 모니터는 실행 화면입니다. 문장을 하나 켤 때마다 프롬프트에 그 줄이 추가되고, 같은 순간 고양이가 그 동작을 얻습니다. 마음에 드는 조합을 만든 뒤 프롬프트를 복사해서 실제로 만들어 보세요.

    04 — Loop
    
한 번에 완성되지 않는다

    
바이브코딩의 실력은 첫 프롬프트가 아니라 두 번째 프롬프트에서 갈립니다.
      실제 수업에서 나온 순서 그대로 따라가 봅시다.

  

  

    

    

  







  

    05 — Mapping
    
내 문장이 어느 줄이 되었나
